Product Document · v0.4

电子宠物：让每一次练习都有回应

宠物功能不是独立小游戏，而是挂在现有学习闭环上的反馈层：学生完成单元、知识点或题库练习后，答题结果转化为经验与食物；食物进入背包，由学生手动喂养，转化为饱腹度与成长，并在关键等级触发进化。本文档基于当前产品结构（学段 / 年级 / 教材版本 / 科目 / 章节 / 单元 / 知识点 / 题库 / 错题本 / 学习统计）定义 5 种宠物、食物系统、等级进化、领养登记、喂养记录，并给出对应的数据库表结构与接口草案。

版本 v0.4（食物背包与手动喂养；用户-宠物关系独立建表，方案待评审） 端 移动端（学生）、管理后台（配置） 目标用户 小学至高中学生 依赖 现有练习结算、学习统计、用户学段资料

1. 结合现有产品逻辑

当前 App 的学习闭环是：选择教材与科目 → 按章节/单元练习，或按知识点练习，或进入题库练习 → 提交结算 → 查看正确率、用时与错题回顾 → 在「学习统计」查看进度。宠物功能只在结算成功之后插入一层反馈，不新增学习路径、不改变练习规则；喂养是结算之后的独立动作，不影响练习流程。

2. 目标与范围

目标

  • 学生完成练习后，能立即看到两件事：获得多少经验、获得哪些食物。
  • 学生打开宠物页能看懂三件事：当前状态、背包里有什么、下一次进化还差多少。
  • 喂养是一个低压力动作：宠物不会饿死、不会离开，饱腹度只影响视觉反馈。
  • 宠物成为「学习统计」之外的情感化呈现，但不替代原有数据与错题功能。
P0 采用「答题得经验 + 答题得食物 + 手动喂食」的完整闭环；P1 做分享与筛选增强
层级内容说明
P05 种宠物领养、首页宠物卡片、宠物详情页、食物背包、答题发放经验与食物、手动喂养、等级与进化、喂养记录、每日上限与防刷、结算页反馈、后台配置构成完整闭环
P1进化动画分享、按学段推荐种类、喂养记录筛选、饥饿提醒、互动动作、改名、外观道具增强陪伴感与可运营性
不做宠物死亡与惩罚、抽卡与付费、多宠物同时养成、宠物对战、社交排行与目标用户年龄及「不制造焦虑」定位冲突

3.4 食物系统

食物数值为建议值 待评审
食物获得方式效果每日上限
🍎 普通食物每答对 1 题获得 1 个饱腹度 +1030 个 / 日；题库来源最多 15 个 / 日
🍰 高级食物单次练习最长连对 ≥ 5 题获得 1 个饱腹度 +30，经验 +55 个 / 日
⭐ 稀有食物完成一个单元获得 1 个饱腹度 +50，经验 +15，随机外观道具（P1）2 个 / 日

获得规则：

  • 所有食物在练习结算成功后发放，进入背包，不直接增加饱腹度。
  • 「完成一个单元」指本次为章节练习、题量 ≥ 10 且提交了该单元全部题目；题库与知识点练习不发放稀有食物。
  • 食物只增不减地进入背包，可跨天保留；未喂食不会过期。
  • 风控拦截、未领养、重复结算均不发放食物。
  • 食物发放数量受「每日经验上限」与「每日食物数量上限」双重约束，超出部分不补发。

喂食规则：

  • 喂食由用户手动触发，一次可选择 1–10 个同类型食物。
  • 饱腹度上限 200；超出部分不增加饱腹度，但经验照常发放（未达每日经验上限时）。
  • 饱腹度已满时禁止喂食，提示「宠物吃饱了，明天再来喂吧」，食物保留在背包。
  • 每日经验已达上限时仍可喂食获得饱腹度，经验为 0，提示「今日经验已满，明天继续」。

3.5 饱腹度、状态与衰减

状态实时计算，只影响展示，不影响经验与等级
状态判定文案方向可执行操作
精神饱腹度 ≥ 70活跃，鼓励保持节奏查看、去练习、喂食（未满时）
正常30 ≤ 饱腹度 < 70平静，提示背包里还有食物查看、去练习、喂食
饥饿饱腹度 < 30 且今日未喂食低落，提示「做几道题就能换到食物」查看、去练习、喂食
沉睡连续 72 小时无喂食睡眠，不指责用户查看、去练习、喂食
  • 每满 1 小时饱腹度 -5；不足 1 小时的余量累计到下次，不做每日零点结算。
  • 衰减在读取宠物数据时按真实经过小时数一次性补齐，最低 0；离线超过 30 天只补算 720 小时并直接置 0。
  • 衰减基准为服务端时间戳（lastDecayAt），修改设备时间不影响已记录数据。
  • 饱腹度不参与等级、阶段、错题与学习统计的任何计算。

4. 功能需求

FR-01 领养与登记

建立宠物档案

入口：首页宠物卡片、宠物页引导、练习结算页领养提示（未领养时）。

流程：领养引导 → 查看 5 种宠物（形象 + 主题 + 进化路线）→ 选择 1 种 → 输入昵称 → 确认领养。

登记字段：

字段来源规则
宠物种类用户选择必选，领养后不可更换
昵称用户输入1–8 字符，允许中英文与数字，敏感词拦截
所属学段读取用户资料只读展示；资料缺失时显示「未设置」
领养时间系统记录作为宠物「生日」与陪伴天数起点
初始状态系统设置Lv1、幼年、累计经验 0、饱腹度 60、背包为空

规则：昵称为空、超长或命中敏感词时禁止提交并说明原因；领养在事务内创建宠物与 UserPet 关系（isPrimary = true），同一用户重复提交只生成一只宠物；宠物页展示「陪伴第 N 天」。

FR-02 首页宠物卡片

让宠物在首页被看见

位置：移动端首页顶部轮播下方、快捷入口卡片上方；Web 首页 Hero 区域下方。

展示内容：

  • 宠物当前阶段形象或待机动画，居中展示。
  • 昵称 + 等级，例如「小喵 Lv.12」；跨阶段时附加阶段名。
  • 饱腹度进度条与数值（0–100），仅作视觉反馈。
  • 背包中有食物且饱腹度未满时，卡片右上角显示「可喂养」红点。
  • 点击整卡进入宠物详情页；未领养时展示领养引导卡片。

异常：宠物数据加载失败时卡片降级为「去看看宠物」入口，不阻塞首页其他内容；未领养不显示饱腹度与红点。

FR-03 宠物详情页

状态、成长、背包与喂养入口

区域划分：

  • 形象区：当前阶段形象、昵称、种类名、状态标签。
  • 成长区：等级、阶段、累计经验进度条、距下一级所需经验；接近 Lv10 / Lv20 时展示「即将进化」。
  • 状态区：饱腹度条、状态文案、今日已获经验 / 300。
  • 背包区：三种食物及数量；数量为 0 时置灰并提示「完成练习可获得」。
  • 档案区：陪伴天数、累计答对题数、累计喂养次数、最常学科目（按喂养次数取最多，展示科目图标与名称）。
  • 记录区：最近 3 条喂养记录，底部「查看全部」进入喂养记录页。
  • 主操作：「喂食」打开食物选择；「去练习」打开现有练习入口；「查看进化路线」展示三阶段形态。

异常：加载失败提供重试，不阻塞其他页面；未领养直接展示领养引导；配置形象缺失时回退默认形象。

FR-04 答题获得经验与食物

结算时完成一次发放

触发：用户完成一次练习并成功结算（以现有结算接口返回成功为准，客户端动画不参与计算）。

不同练习来源的发放差异，数值为建议值 待评审
来源对应现有入口答题经验普通食物高级 / 稀有
单元练习我的教材 → 章节 → 单元+1 / 答对题+1 / 答对题连对 ≥5 得高级；完成单元得稀有
知识点练习按知识点学+1 / 答对题+1 / 答对题连对 ≥5 得高级；不发稀有
题库练习题库 / 错题重做+1 / 答对题+1 / 答对题（每日最多 15 个）连对 ≥5 得高级；不发稀有

计算规则：

  • 答题经验 = 答对题数 × 1 + min(本次最长连对, 10)，再与「每日经验剩余额度」取最小值。
  • 普通食物数量 = 答对题数，受每日 30 个与题库 15 个的上限约束。
  • 高级食物：单次最长连对 ≥5 发放 1 个，每日最多 5 个。
  • 稀有食物：章节练习且题量 ≥10 视为完成一个单元，发放 1 个，每日最多 2 个。
  • 同一结算标识只生成一条发放记录；重复提交、网络重试不重复发放。
  • 同一题目在同一自然日只计一次经验与食物；错题重做同样受限。
  • 中途退出、未提交、结算失败、未作答均不发放。

结果：结算页展示本次获得经验、获得食物、今日累计、是否触发上限、是否升级或进化；点击进入宠物页完成喂养。

FR-05 喂养

把食物转化为饱腹度与经验

入口：宠物详情页「喂食」；首页宠物卡片红点提示。

流程：打开食物选择 → 选择食物类型与数量（1–10）→ 确认喂食 → 播放进食动画 → 饱腹度与经验数字滚动 → 若升级或进化则继续播放对应动画。

规则：

  • 只能喂背包中已有且数量足够的食物；数量不足时不可提交。
  • 饱腹度已满时禁止喂食，提示「宠物吃饱了，明天再来喂吧」，食物保留。
  • 饱腹度未满但溢出时不浪费经验；溢出部分不加饱腹度。
  • 每日经验已达上限时仍可喂食，经验为 0 并明确提示。
  • 一次喂食对应一条喂养记录；并发或重复提交以服务端第一次结果为准。
  • 喂养不改变练习记录、错题与学习统计。
FR-06 升级与进化

等级、阶段与形象切换

  • 经验增加后即时重算等级；跨过 Lv10 或 Lv20 时触发进化。
  • 进化时播放该阶段的全屏动画，展示新形态与新名称（如「成猫」「魔法猫」）。
  • 等级、阶段与已解锁形象只升不降；饥饿、沉睡、多日未学习均不影响。
  • 阶段变化后首页卡片、宠物页与档案区形象同步切换；已解锁的旧阶段形象可在「进化路线」中查看。
  • 满级后继续累计经验，进度条展示为满格与「已长大」。
  • 等级换算与阶段阈值由后台配置；调整后已达成阶段不回退，下一级按新阈值计算。
  • 进化动画播放失败或用户跳过时，数值与形态已经生效，不重复播放。
FR-07 饱腹度与衰减

状态维持

  • 饱腹度 0–200；喂食时按食物效果增加，超过 200 按 200 计。
  • 每满 1 小时衰减 5（不足 1 小时的余量累计到下次）；读取时按真实经过小时数一次性补齐。
  • 衰减在读取宠物数据时按小时差一次性补齐，最低 0，最多补算 30 天（720 小时），超出直接置 0，不做定时任务。
  • 衰减基准为服务端时间戳；修改设备时间不影响已记录数据。
  • 饱腹度不参与等级、阶段、错题与学习统计的任何计算。
  • 饱腹度与状态不导致宠物死亡、离开或经验扣除。
FR-08 喂养记录

可追溯的喂养明细

入口：宠物页「查看全部」；结算页「查看本次记录」。

页面结构：

  • 顶部汇总：今日经验 / 300、今日喂食次数、累计喂养次数。
  • 记录列表：按时间倒序，每行展示：日期时间、食物类型与数量、饱腹度增加、经验增加、是否升级或进化。
  • 补充来源：由练习发放的食物可在记录中回溯到来源（单元 / 知识点 / 题库）、科目、章节或知识点名称。
  • 分页：每页 20 条，下拉加载更多。
  • 范围：保留 90 天，页面仅展示最近 30 天；更早数据在后台可查。
  • P1：按食物类型与科目筛选。

异常：无记录时展示空状态与「去练习」；加载失败可重试且不清空已加载数据。

FR-09 每日上限与防刷

激励边界

  • 每日经验上限 300，答题经验、连对奖励、食物经验与登录奖励合计。
  • 食物数量上限：普通 30（题库来源 15）、高级 5、稀有 2；超出不发放、不结转到次日。
  • 经验与食物只来源于正常练习结算、喂食与每日首次登录；不提供购买经验、分享得经验或直接补发的入口。
  • 同一练习结算幂等；同一题目同日只计一次；同一喂食请求幂等。
  • 异常答题（如每题耗时异常短、题量异常大）按 0 经验、0 食物结算；用户侧只提示「本次练习未获得奖励」，不暴露风控细节。
  • 达到上限后仍可正常学习、喂养与查看错题，仅经验不再增加；文案保持正向。
FR-10 结算页反馈

在现有结果页增加一层

  • 位置：正确率、题量、用时与错题回顾之后，不遮挡原有信息。
  • 内容：本次获得经验、获得食物（普通 / 高级 / 稀有）、今日累计 / 上限、升级或进化提示、宠物一句话回应。
  • 已领养：展示宠物当前阶段小图 +「去喂养它」；未领养：展示领养引导。
  • 经验或食物为 0（上限、风控、未答对）时展示对应原因文案，不显示为错误或失败。
  • 不新增独立结算步骤，不打断原有「再练一次 / 继续学习」流程；喂养入口为可选跳转。

FR-12 与学习统计的一致性

  • 发放记录与喂养记录中的答对题数来自该次练习结算明细，与结果页展示一致。
  • 宠物页不新增「学习时长」等重复指标，避免与学习统计页冲突。
  • 学习统计页不展示宠物数据；两个页面通过「去练习」互相导流即可。

5. 共享规则与异常

5.1 发放与幂等

  • 经验与食物的唯一发放来源为练习结算；一次结算最多对应一条发放记录。
  • 结算标识重复上报不产生第二条记录，经验、背包与宠物数值不变。
  • 结算与喂食的具体数值以服务端返回为准，客户端不自行累加。
  • 喂食在事务内完成扣减背包、增加经验/饱腹度、写入记录；任一步失败则整体回滚。

  • 领养转化率：从入口曝光到完成领养的比例。
  • 喂养覆盖率：日活学生中当日完成至少一次喂食的比例。

  • 上限触达率：触发每日经验或食物上限的用户比例，用于校准数值。
  • 负向信号：经验为 0 的比例、饥饿/沉睡状态占比、进化动画跳过率。

指标基线 待定，以现有学习统计数据为准，不在此处编造目标值。

9. 表结构（Prisma 草案）

沿用现有 schema.prisma 约定：业务主键用 String @default(uuid())，字典类用 BigInt @default(autoincrement())，状态用字符串常量。本方案新增 9 张表（含独立的 UserPet 关系表），并在 User 上补 5 个反向关系；不修改既有 StudyAttempt、Question 等表结构。与参考文档的差异：用户与宠物关系独立建表，种类主键保持 BigInt，食物背包按类型聚合而非一行一个，经验与饱腹度分字段存储。

model PetSpecies {
  id        BigInt   @id @default(autoincrement())
  code      String   @unique            // cat / dog / rabbit / fox / bird
  name      String                      // 小猫 / 小狗 / 小兔 / 小狐 / 小鸟
  theme     String?                     // 可爱系 / 忠诚系 / 灵动系 / 智慧系 / 自由系
  tagline   String?                     // 领养页的一句性格文案
  sortOrder Int      @default(0)
  enabled   Boolean  @default(true)
  createdAt DateTime @default(now())

  stages PetSpeciesStage[]
  pets   Pet[]

  @@index([sortOrder])
}

// 每个种类 3 个阶段；缺失动画时回退静态图
model PetSpeciesStage {
  speciesId       BigInt
  species         PetSpecies @relation(fields: [speciesId], references: [id], onDelete: Cascade)
  stageKey        String                       // juvenile / growing / mature
  name            String                       // 幼猫 / 成猫 / 魔法猫
  imageUrl        String
  idleLottieUrl   String?                      // 待机动画
  feedLottieUrl   String?                      // 进食动画
  evolveLottieUrl String?                      // 进入该阶段的进化动画（幼年为空）

  @@id([speciesId, stageKey])
}

model Pet {
  id                  String   @id @default(uuid())
  speciesId           BigInt
  species             PetSpecies @relation(fields: [speciesId], references: [id])
  nickname            String                   // 1-8 字符，敏感词在接口层拦截
  stageId             BigInt?                  // 领养时的学段快照（小学 / 初中 / 高中）
  stageName           String?                  // 学段名称快照，接口中输出为 schoolStageName
  level               Int      @default(1)     // 由 experience 推导后落库，便于列表展示
  experience          Int      @default(0)     // 累计经验，只增不减
  satiety             Int      @default(60)    // 0-200
  lastDecayAt         DateTime @default(now()) // 按完整小时累计的衰减基准
  lastLoginRewardDate DateTime? @db.Date       // 每日首次登录奖励
  adoptedAt           DateTime @default(now())
  lastFedAt           DateTime?
  createdAt           DateTime @default(now())
  updatedAt           DateTime @updatedAt

  userPets    UserPet[]
  foodGrants  PetFoodGrant[]
  feeds       PetFeedLog[]

  @@index([speciesId])
}

// 用户与宠物的关系单独维护：P0 每人一只，未来可扩展为多只
model UserPet {
  id        String   @id @default(uuid())
  userId    String
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  petId     String   @unique            // 一只宠物只属于一个用户
  pet       Pet      @relation(fields: [petId], references: [id], onDelete: Cascade)
  isPrimary Boolean  @default(true)     // 当前展示与喂养的宠物
  adoptedAt DateTime @default(now())

  @@index([userId, isPrimary])
}

// 背包库存：按用户 + 食物类型聚合，跨天保留
model PetFoodItem {

11. 关键算法

11.1 日期键

与现有 UserDailyStat 保持一致：const today = new Date(); today.setHours(0, 0, 0, 0); 作为 dateKey。每日经验上限、食物上限、登录奖励、免衰减与记录分页均以该日期键为准，不使用客户端时间。

11.2 结算（在 finish 内完成）

  • 校验参数与 clientSessionId；按 UserPet.isPrimary 读取用户当前宠物、配置与当日汇总；未领养则跳过发放，仅写学习事实。
  • 风控判定：durationSeconds / totalQuestions < minSecondsPerQuestion 或 totalQuestions > maxQuestionsPerAttempt 时，经验与食物均计 0。
  • 在单个事务内依次完成：创建 StudyAttempt 与 StudyAttemptItem（沿用现有逻辑）→ 创建 PetFoodGrant → 累加背包 → 更新 Pet（经验、等级）→ 更新 PetDailyStat。
  • 唯一约束冲突（userId + clientSessionId）时不重复发放，读取已有记录并返回首次结果。
// 结算计算（伪代码）
const baseExp = riskBlocked ? 0 : correctCount * config.expPerCorrect;
const streakExp = riskBlocked ? 0 : Math.min(maxStreak, config.streakBonusMax);
const expGain = Math.max(0, Math.min(
  baseExp + streakExp,
  config.dailyExpCap - daily.expGained
));

const normal = riskBlocked ? 0 : Math.max(0, Math.min(
  correctCount,
  config.normalFoodDailyCap - daily.foodNormal,
  scopeType === "bank"
    ? config.bankNormalFoodDailyCap - daily.bankFoodNormal
    : Infinity
));
const premium = riskBlocked || maxStreak < config.premiumStreak ? 0 : Math.max(0, Math.min(
  1, config.premiumFoodDailyCap - daily.foodPremium
));
const rare = riskBlocked || !isUnitCompleted ? 0 : Math.max(0, Math.min(
  1, config.rareFoodDailyCap - daily.foodRare
));

// 落库后
pet.experience += expGain;
pet.level = Math.min(config.maxLevel, Math.floor(pet.experience / config.expPerLevel) + 1);
// 背包：对应类型 quantity += normal / premium / rare
// 每日汇总：foodNormal += normal；bank 来源同时累加 bankFoodNormal；
//           foodPremium / foodRare / expGained 同步累加

11.3 喂食

// 校验：食物存在、数量 1-10、库存足够、饱腹度未满
if (pet.satiety >= config.satietyMax) return 409 PET_FULL;
if (inventory[foodType] < quantity) return 400 FOOD_NOT_ENOUGH;

const satietyGain = Math.min(
  quantity * satietyPerFood[foodType],
  config.satietyMax - pet.satiety
);
const expGain = Math.min(
  quantity * expPerFood[foodType],
  Math.max(0, config.dailyExpCap - daily.expGained)
);

const levelBefore = pet.level;
const stageBefore = deriveStage(levelBefore);
pet.satiety += satietyGain;
pet.experience += expGain;
pet.level = Math.min(config.maxLevel, Math.floor(pet.experience / config.expPerLevel) + 1);
const stageAfter = deriveStage(pet.level);

// 事务内：扣减背包 → 写 PetFeedLog → 更新 Pet → 更新 PetDailyStat（feedCount、satietyGained）

饱腹度溢出部分不增加；经验已达上限时为 0，但仍写喂养记录，便于学生看到「吃饱了但今天经验满了」的反馈。

11.4 每日首次登录奖励

// GET /api/app/pet 内执行，只对已领养用户
if (pet.lastLoginRewardDate !== today) {
  const gain = Math.max(0, Math.min(
    config.dailyLoginExp,
    config.dailyExpCap - daily.expGained
  ));
  pet.experience += gain;

登录奖励只增加经验，不进入喂养记录；若当日经验已达上限则发放 0，但仍更新日期，避免次日重复领取。

11.5 饱腹衰减（读取时补齐）

不做定时任务。每次读取宠物（首页、详情、结算）时，按 lastDecayAt 与当前时间的「完整小时数」一次性结算：每满 1 小时扣 satietyDecay，不足 1 小时的余量保留到下次；饱腹度最低 0。最多补算 30 天（720 小时），超出部分直接置 0 并把 lastDecayAt 更新为当前时间。没有完整小时可结算时不写库，避免「扣 0 却推进基准」。

// 伪代码
const hours = Math.floor((now - pet.lastDecayAt) / 3600_000);
if (hours <= 0) return pet;
const settled = Math.min(hours, 720);
pet.satiety = Math.max(0, pet.satiety - settled * config.satietyDecay);
pet.lastDecayAt = hours > 720 ? now : addHours(pet.lastDecayAt, settled);

11.6 状态派生

状态派生条件
activesatiety ≥ 70
normal30 ≤ satiety < 70
hungrysatiety < 30 且当日 feedCount = 0
asleep距 lastFedAt 超过 72 小时（无记录时按 adoptedAt 计算）

状态不落库，只作为接口出参；优先级 asleep > hungry > normal > active，避免同一时刻出现两种状态。
